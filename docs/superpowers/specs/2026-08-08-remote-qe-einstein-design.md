# Remote QE on Einstein (Mac disk + Einstein CPU) — Design Spec

Date: 2026-08-08  
Status: approved for planning  
Branch: `HTML_einstein_app` (scripts live in repo; no merge to `main` required for use)  
Related: Track B QE install on Einstein (`~/miniconda3/envs/qe`)

## Problem

Einstein has strong CPU/RAM but a nearly full root disk and no sudo for sandy to mount the idle 1 TB drive. The Mac Studio has disk and local QE for input generation. User wants **compromise option 1**: keep data on Mac, run heavy QE on Einstein via rsync + SSH, then pull only small products back.

Wannier/QE intermediates (wfc, UNK, `.chk`) can be multi‑GB: they must exist on Einstein **during** the run, but need not stay there or transfer home by default.

## Goals

- CLI script on Mac: sync a TensorSpec QE run directory → Einstein scratch → run `pw.x` (+ optional nscf / pw2wannier90 / wannier90) → pull allowlist → wipe scratch on success.
- Scratch root: `/data/sandy/qe_scratch` if writable, else `$HOME/qe_scratch`.
- Default pull: `wannier90_hr.dat` + logs/`scf.out` (and small siblings); not wfc/UNK/`.chk`.
- Document usage and limits (disk, no web UI yet).

## Non-goals

- Web “Queue on Einstein” button (later).
- ARPES matrix-element remote runner (later).
- SSHFS / NFS mounts.
- Pulling full `outdir` / UNK / `.chk` by default.
- Fixing Einstein GPU drivers or mounting `/data` (sysop).

## Decisions (locked)

| Topic | Choice |
|-------|--------|
| Delivery | Bash CLI only (`scripts/remote_qe.sh`) |
| Workload | QE (+ optional Wannier chain if inputs present) |
| Pull | Minimal: hr.dat + logs/scf.out (+ small outs) |
| Scratch | Prefer `/data/sandy/qe_scratch`, else `~/qe_scratch` |
| Failed jobs | Keep remote scratch; still pull `scf.out` / log |
| Host | `einstein` (overrideable) |

## Architecture

```
Mac run_dir (scf.in, pseudo/, …)
    │ rsync -az
    ▼
Einstein $SCRATCH/<job_id>/
    │ mpirun pw.x → optional nscf → pw2wan → wannier90
    │
    ├─ success: rsync allowlist → Mac; rm -rf scratch
    └─ failure: rsync scf.out + log → Mac; keep scratch
```

Solver binaries (Einstein): prefer sourcing `~/tensorspec-solvers.env`, else  
`$HOME/miniconda3/envs/qe/bin/{pw.x,mpirun,pw2wannier90.x,wannier90.x}`.

## §1 — Script behavior

### Usage

```bash
./scripts/remote_qe.sh <local_run_dir> [--np 4] [--host einstein] [--keep-scratch] [--dry-run]
```

### Local run dir requirements

- Must contain `scf.in`
- Should contain `pseudo/` (or UPF paths valid relative to run dir as generated by TensorSpec)
- Optional: `nscf.in`, `pw2wan.in`, `wannier90.win` → run those steps if present

### Remote scratch

```
SCRATCH_ROOT = /data/sandy/qe_scratch   # if /data/sandy exists and is writable
             | $HOME/qe_scratch         # fallback
SCRATCH      = $SCRATCH_ROOT/<job_id>/
job_id       = YYYYMMDD-HHMMSS-<basename>
```

### Pipeline on Einstein

1. `mpirun -np N pw.x -in scf.in | tee scf.out`
2. If `nscf.in`: same for nscf → `nscf.out`
3. If `pw2wan.in` and `wannier90.win`:
   - `pw2wannier90.x < pw2wan.in | tee pw2wan.out` (or project’s usual invocation)
   - `wannier90.x wannier90 | tee wannier90.wout` (serial OK)

Detect SCF success via exit code and/or `JOB DONE` in `scf.out`.

### Pull allowlist (default)

- `scf.out`, `nscf.out` (if any)
- `pw2wan.out` (if any)
- `wannier90.wout` / `*.wout`
- `wannier90_hr.dat`
- `remote_qe.log` (script transcript)

**Never** in default mode: `outdir/`, `*.wfc`, `UNK*`, `*.chk`.

### Flags

| Flag | Meaning |
|------|---------|
| `--np N` | MPI ranks (default 4, max 32) |
| `--host` | SSH host (default `einstein`) |
| `--keep-scratch` | Do not delete remote dir after success |
| `--dry-run` | Print planned steps; no rsync execute / no remote run |

## §2 — Errors, guards, docs

### Exit codes

| Code | Case |
|------|------|
| 1 | SSH / connectivity |
| 2 | Local validation (`scf.in` missing, path not a run dir) |
| 3 | Remote `pw.x` missing |
| 4 | SCF (or chain) failed — scratch kept; outs pulled if present |
| 5 | Remote free disk &lt; ~1 GB before start |

### Guards

- Refuse syncing the whole git repo: require `scf.in` in the target directory.
- Cap `--np` at 32.
- Preflight `df` on scratch filesystem.

### Docs

- `scripts/README-remote-qe.md`: usage, scratch policy, minimal pull, Einstein QE paths, relationship to DFT Suite Generate/Bundle (local) vs this runner (remote execute).

### Tests / verification

- `--dry-run` smoke on Mac without Einstein.
- Manual: one small SCF against Einstein when network available.
- No CI that SSHs to Einstein.

### Success criteria

1. Prepared Mac run dir → remote SCF completes.
2. Mac gains `scf.out` and, if Wannier ran, `wannier90_hr.dat`.
3. On success, Einstein scratch removed unless `--keep-scratch`.

## Out of scope (later)

- Wire into HTML DFT Queue as `backend=einstein-ssh`
- Remote ARPES ME runner
- Default pull of `.chk` / full outdir
